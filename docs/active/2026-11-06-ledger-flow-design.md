# 2단계 돈의 흐름 연결 설계서 (2026-11-06)

상태: **2단계 완료(2026-11-06). 라이브 적용·검증 끝.** 1단계 [장부 뼈대](2026-11-06-ledger-foundation-design.md)에 이어집니다.
범위: 후원·기타 수입·지출·급여·정산 입금이 전표로 자동 연결되고, 결재 승인과 실제 지급을 나눕니다.

## 한눈에 보기

| 돈 | 언제 | 장부에 기록되는 내용 |
|---|---|---|
| 계좌이체 후원 | 입금 확인 완료 | 차변 보통예금 / 대변 기부금수익 |
| 카드·CMS 후원 | 결제 완료 | 차변 결제 정산 미수금 / 대변 기부금수익 |
| 카드·CMS 정산 입금 | 통장 묶음 입금 분류 | 차변 보통예금 / 대변 결제 정산 미수금 |
| 후원 환불·취소 | 상태 변경 | 반대 전표 자동 |

## §0. 결정

| # | 항목 | 결정 | 이유 |
|---|---|---|---|
| 1 | 자동화 방식 | 결제 코드에 끼워 넣지 않고 원천 표를 훑어 전표를 만든다 | 후원 기록 경로가 45곳 넘음. 결제 흐름을 건드리면 위험하고 한 곳이 빠지면 누락됨. 훑기는 경로가 늘어도 누락이 없음 |
| 2 | 실행 시점 | 매일 KST 03:00(기존 03:00 크론과 정렬), 장부의 «지금 반영», 월 마감 직전, 지급 확인·지출 승인 직후 | DB 상시 가동 방지 |
| 3 | 후원금 계정 | 기부금수익(개인) 4011, 재원 기부금 | 정관 제6조⑤, 공시 표준서식 |
| 4 | 수수료 | 정산 입금은 받은 금액만 미수금에서 뺀다. 남는 미수금은 정산 전 금액이거나 수수료이며 자금 연결에서 보이고 수수료 전표로 정리 | 묶음 입금에서 건별 수수료를 알 수 없음 |
| 5 | 결재 | **승인 = 예약, 지급 확인 = 지출·전표.** 승인만으로는 손익·집행에 들어가지 않고 예약액에 잡힘 | 로드맵 §6 |
| 6 | 태그 입력 | 결재 기안과 지출 입력에서 활동·사업·재원을 받는다 | 지급 때 전표가 바로 승인되려면 필요 |
| 7 | 부족한 전표 | 계정이나 태그가 부족하면 작성중 전표로 남긴다. 마감에서 막힌다 | 틀린 전표를 자동 승인하지 않음 |
| 8 | 재실행 | 같은 출처는 전표가 두 번 만들어지지 않는다. 운영자가 취소한 자동 전표는 다시 만들지 않는다 | 운영자가 손으로 고칠 수 있어야 함 |
| 9 | 마감된 달 | 늦게 들어온 건은 만들지 않고 «마감된 달 미반영»으로 표시. 해제 후 반영 | 마감을 깨지 않음 |
| 10 | 급여 | 직원별 전표. 활동·사업·재원은 직원별 배부표에서 가져오고 없으면 일반관리·기부금 | 지급 확정분 기준(신고와 같음) |
| 11 | 사업주 부담 4대보험·원천세 납부 | 납부 출금을 통장에서 전표로 처리(차변 예수금·복리후생비) | 급여 명세에 사업주 부담분이 없음 |
| 12 | 통장 | 파일별로 장부 계정을 저장. 우리은행은 전용계좌(1012), 그 외는 기타 계좌(1013) | 전용계좌 대조 |
| 13 | 결재 없는 지출 | 입구는 두고 표시한다 | Swain 결정 |

## §1. DB

마이그: `migrate-ledger-flow` (`?run=1`, `?cleanup=1`)

| 표 | 추가 |
|---|---|
| `approval_requests` | `function_code`, `program_id`, `fund_id`, `payment_status`('none'·'unpaid'·'paid'), `paid_at`, `paid_by`, `bank_txn_id`, `pay_account_code` |
| `expenses` | `account_code`, `function_code`, `program_id`, `fund_id`, `bank_txn_id`, `pay_account_code` |
| `revenue_categories` | `account_code` (기존 6개 초기값) |
| `bank_imports` | `account_code` |
| `budget_account_code_map` | 예산 목 22개 ↔ 계정 초기값 |
| `ledger_staff_allocations` 신규 | `member_id`, `function_code`, `program_id`, `fund_id` |

기존 승인 결재는 `payment_status='paid'`로 채웁니다(이미 지출 생성됨).

수입 분류 연결: 강연·교육 4014, 정부·지자체 지원금 4012, 기업 협찬·제휴 4015, 함께워크 On·SI 4014, 기타 4022.

## §2. API

| 경로 | 권한 | 역할 |
|---|---|---|
| `POST /api/admin-ledger-sync` | finance_bookkeeping | 지금 반영 |
| `GET /api/admin-ledger-flow` | finance_view | 자금 연결 현황 |
| `POST /api/admin-approval-pay` | finance_bookkeeping | 지급 확인 |
| `GET /api/admin-ledger-tags` | 어드민 | 활동·사업·재원·비용 계정 목록(기안 창용) |

## §3. 화면

- 장부 › **자금 연결** 탭: 자동 전표 현황과 지금 반영, 통장 잔액 대조, 정산 미수금, 미지급 결재와 지급 확인, 결재 없는 출금, 결재 없는 지출.
- 장부 › 기준 정보: 수입 분류 연결, 인건비 배부 추가.
- 지출 결재 기안 창: 활동·사업·재원 입력. 지출결의서 목록에 지급 상태 표시.
- 지출 등록 창: 계정·활동·사업·재원·지급 방법 입력.
- 통장 업로드: 우리은행 파일 인식.

## §4. 검증

실제 코드를 로컬 임시 DB에 붙여 74개 통과(후원, 환불, 정산 입금, 수입, 결재, 지급, 취소, 지출, 환불, 급여, 마감). 라이브는 2099 시험 연도로 시나리오 32개와 화면 조작 29개 통과 후 정리.

라이브에서 찾아 고친 문제: 수입 조회와 취소 전표 조회의 별칭이 겹쳐 전표가 된 수입이 미반영으로 잡혔습니다. 유일 제약이 중복을 막아 건수로만 드러났습니다.

후원과 급여는 시험 데이터를 넣을 경로가 없어 라이브에서 돌리지 않았습니다. 실제 후원이 들어오는 첫날 자금 연결에서 확인해야 합니다. 우리은행 파일은 예상 양식으로 만든 파일로만 시험했습니다.

## §5. 한계

- 법인 후원 구분 칸이 없어 후원금은 전부 개인으로 잡힙니다. 법인 후원은 전표를 취소하고 4015로 다시 씁니다.
- 수수료는 건별 자동 계산이 아닙니다(§0-4).
- 인건비 배부는 직원당 활동 하나입니다. 비율 배부는 3단계에서 판단합니다.
