## 2. 검증

- 로컬 가짜 서버로 **서버 렌더 상태를 흉내**(`MOCK_SSR=1`) + 라이브 배포본 JSON 고정 응답 →
  - 수정 전 `common.js`: 퀵메뉴 = 코드 기본값 6개 / 히어로 = 코드 기본 문장 (**① 재현**)
  - 수정 후 `common.js`: 퀵메뉴 = 주요 활동·유가족 이야기·악성 민원 신고·법률 지원 서비스·후원하기·공지사항 / 히어로 = DB 1번 슬라이드 (**① 해결**)
- 1차 배포(① 만 적용) 뒤 라이브 확인에서 **여전히 기본값** → 콘솔엔 적용 기록이 찍히는데 화면이 안 바뀜 → 심어 둔 값(`__SIREN_PRELOAD__`)의 모양 차이 발견(**②**).
  로컬에 수정 전 라이브가 심던 평면 값을 그대로 주입(`?mockpre=1`)해도 새 `home.js`가 정책국장 편집값을 그림 — 그리고 서버는 더 이상 평면 값을 심지 않음.
- 다른 페이지(공지·추모관·활동) 콘솔 오류 0. `node --check`·`tsc` 통과.
- 어드민 공지 작성 창: 썬에디터 생성·사진 단추 확인(로컬).
- 라이브 E2E 스크립트(scratchpad `e2e-live.mjs`): 활동 정렬·어드민 마크업·편지 쓰기 등 20/20 통과(추모관 포함).

## 5. 교훈 (재발 주의)

- **서버 렌더(SSR)를 도입하면 "비동기 기다림"에 기대던 초기화 순서가 깨진다.** 8-20에 조각을 미리 채우자 `await loadAllPartials()`가 즉시 끝났고, 그 뒤에 오는 스크립트의 등록을 기다리던 호출이 빈손으로 지나갔다. 순서는 **이벤트(DOMContentLoaded)** 로 못 박을 것, 네트워크 지연에 기대지 말 것.
- **"브라우저가 다시 조회하지 않게 값을 미리 심는다"면 그 값은 반드시 API와 같은 함수로 만들 것.** 저장소 모양을 그대로 심으면 화면이 못 알아듣는데, 심어 둔 값이 있으니 API도 안 불러 **조용히** 실패한다. 콘솔에 "적용" 로그가 찍히는데 화면이 안 바뀌면 이 경우부터 의심.
- 1차 수정 뒤 **라이브에서 다시 확인**하지 않았다면 ②를 놓쳤다. 로컬 재현이 통과해도 라이브 검증은 생략하지 말 것(로컬 가짜 서버는 preload를 심지 않았다).
- 같은 종류의 다른 화면 스크립트(활동·후원·인증 등)는 자체 안전망(직접 init 호출)이 있어 티가 안 났고, 홈만 없어서 드러났다. 새 화면 스크립트는 `SIREN_PAGE_INIT` 등록 + `SIREN.pageInitDone()` 확인을 함께 둘 것.
- 「관리자에서는 되는데 주소로 들어가면 안 된다」= 미리보기 경로와 일반 경로의 **타이밍·캐시 차이**부터 의심.
