# 급여 지급 결재 설계서 (2026-11-07)

상태: 구현 완료, 배포, 라이브 쓰기 경로 점검 21개 통과(2026-11-08, 점검용 급여 1건으로 결재 올리기→상신→승인→지급 확인까지 실제 DB에서 돌린 뒤 자동 삭제). 1회용 점검 파일은 삭제했다.
결정: Swain 2026-11-07 «A안 추천으로 진행해». 급여 대장을 결재 문서 한 장으로 올려 승인받고, 지급 확인 때 급여를 한꺼번에 지급 완료로 바꾼다.

## 한눈에 보기

### 왜 만들었나

급여는 급여 관리에서 [지급]을 누르면 결재 없이 장부로 들어갔다. 결재 쪽에는 «고정 인건비» 지출결의서가 따로 있었고 둘이 서로를 몰랐다. 사단법인이 급여를 주기 시작한 뒤 둘 다 쓰면 인건비가 장부와 예산에 두 번 잡힌다(2026-11-07 점검에서 발견). 지금은 급여를 법인화 전 임의단체가 지급하고 있어 실제 영향은 없었다.

### 무엇이 바뀌나

| 구분 | 전 | 후 |
|---|---|---|
| 사단법인 급여 지급 | 급여 관리 [지급] | 급여 관리 [지급 결재 올리기] → 결재 승인 → 지출완료 확인 |
| 다른 사업자 급여 | 급여 관리 [지급] | 그대로 |
| 장부 | 급여 전표 | 급여 전표(그대로). 결재 문서는 지출을 만들지 않는다 |
| 예산 | 지급 뒤 집행만 | 승인 때 기본급·상여금 과목별로 예약, 지급 뒤 집행 |
| 손으로 쓴 결의서 | 급여 예산도 선택 가능 | 기본급·상여금 예산은 상신 차단 |

### 바뀌지 않는 것

급여 계산, 명세서 발송과 전자서명, 원천징수 집계(지급일 기준), 급여 전표의 계정과 인건비 배부, 일반 지출결의서의 흐름.

## §0. 결정과 이유

| # | 결정 | 이유 |
|---|---|---|
| 1 | 대상은 사단법인 소속 급여만 | 결재와 예산은 사단법인 것이다. 판정은 자동 전표와 같은 기준을 쓴다(완료된 근로계약의 사업자 번호, 계약이 없으면 인건비 배부를 저장한 직원). **2026-11-10: 그 달에 유효한 계약으로 판단한다** — 계약 시작일이 급여 달 말일 이전인 완료 계약 가운데 가장 늦게 시작한 계약. 재계약해도 지난달 급여는 그때 계약의 사업자 기준(직원 2명의 사단법인 전환 계기) |
| 2 | 사단법인 급여는 급여 관리에서 직접 지급 확정 불가 | 직접 확정을 남기면 결재를 건너뛸 수 있다 |
| 3 | 문서는 지출결의서(고정 인건비), 표식은 서버만 쓴다 | 새 문서 유형·새 표 없이 기존 결재 흐름을 그대로 탄다. 마이그 없음. 화면이 보낸 표식은 저장 때 버린다 |
| 4 | 금액은 지급총액. 지출내역은 합계 한 줄 | 예산과 급여 전표가 지급총액 기준이다. 직원별 금액은 문서 본문에 두지 않는다 |
| 5 | 직원별 금액은 이사장만 열람 | 급여 관리가 이사장 전용이다. 권한을 넓히지 않았다. 결재선의 다른 사람과 재정 열람 권한자는 인원과 합계만 본다. 승인 당시 내용 조회도 같다 |
| 6 | 지급 확인은 이사장만, 금액은 승인액 그대로 | 급여 지급 확정이 원래 이사장 권한이다. 금액이 달라졌으면 취소 후 다시 올린다 |
| 7 | 상신할 때 급여 명세의 지금 금액으로 다시 맞춘다 | 임시저장 단계에서는 급여를 고칠 수 있어야 한다. 승인 대상은 상신 시점 값이다 |
| 8 | 결재 중·완료 급여는 수정·보류·삭제·재집계(강제 포함) 차단 | 결재한 금액과 지급 금액이 달라지면 안 된다. 지급이 끝난 급여를 강제 재집계가 되돌리면 장부 전표와 어긋난다 |
| 9 | 예산은 급여 전표가 잡히는 과목별로 나눠 예약 | 급여는 급여 계정(기본급 과목), 성과·만근 상여는 상여금 계정(상여금 과목)으로 집행된다. 한 과목으로 예약하면 상여가 있는 달에 잘못 막힌다 |
| 10 | 예산 초과는 일반 문서와 같이 승인 차단 | 이사장이 예산을 조정한 뒤 승인한다(결재 설계서 §0-1). 승인된 예산안이 없는 해는 검사하지 않는다 |
| 11 | 지급 뒤 취소 불가 | 급여 반환은 결재 취소로 다룰 일이 아니다. 급여 정정은 급여 관리의 정정 재발행을 쓴다 |
| 12 | 근로계약이 없는 직원이 들어 있으면 근거 필요 | 설계도 8쪽 고정 인건비 규칙. 계약이 시스템에 있으면 근거가 충족된 것으로 본다. 이사 보수는 이사회 승인 문서를 연결한다(정관 제10조의2③) |
| 13 | 기본급·상여금 예산은 급여 지급 결재 전용 | 손으로 쓴 결의서로 같은 돈을 올리면 지출과 급여 전표가 겹친다 |

## §1. 구조

DB 변경 없음. 급여 지급 결재는 `approval_requests`의 지출결의서이고 `form_data.payroll`에 다음을 둔다.

| 값 | 내용 |
|---|---|
| `year`, `month` | 급여 귀속 월 |
| `slipIds` | 묶인 급여 명세 번호 |
| `count`, `gross`, `deduction`, `net` | 인원, 지급총액, 공제액, 실지급액 |
| `rows` | 직원별 금액. 이사장에게만 내려간다 |
| `budget` | 예산 과목별 금액(기본급, 상여금) |
| `noContract` | 근로계약이 없는 직원 수 |

명세가 문서에 묶였는지는 문서 상태로 판단한다. 임시저장·반려·회수는 묶여 있지만 잠그지 않고, 진행중·완료는 잠근다. 취소·삭제된 문서는 묶음에서 빠진다.

## §2. 처리 흐름

| 단계 | 처리 | 파일 |
|---|---|---|
| 지급 결재 올리기 | 그 달의 사단법인 급여 중 승인·발송된 명세를 모아 임시저장을 만든다. 같은 달에 고칠 수 있는 내 문서가 있으면 그 문서를 다시 맞춘다 | `lib/payroll-approval.ts` `draftPayrollDoc`, `admin-docs` `payroll_draft` |
| 저장 | 제목·내용·결재선만 바뀐다 | `lib/approval-docs.ts` `saveDraft` |
| 상신 | 최신 급여로 다시 맞추고 버전 고정 | `submitDoc` → `refreshPayrollDoc` |
| 최종 승인 | 과목별 예산 검사와 예약, 결의번호 | `finalizeExpense` → `payrollBudgetStep` |
| 지급 확인 | 급여 명세 일괄 지급 완료, 예산 집행 기록, 급여 전표 반영. 지출은 만들지 않는다 | `admin-approval-pay`, `settlePayrollSlips` |
| 지급 전 취소 | 원결재선 승인 뒤 과목별 예약 해제 | `decideCancel` |

예산 예약 합계는 `lib/finance-budget-report.ts`의 `unpaidApprovalsByMok`, `unpaidApprovalsOfMok`가 급여 문서를 과목별로 풀어 센다.

## §3. 화면

- 급여 관리: [지급 결재 올리기] 버튼, 사단법인 급여 안내, 명세 줄의 결재 상태(문서 열기), 사단법인 급여 줄은 [지급] 대신 [결재로 지급]. 결재에 묶인 급여의 상세 창은 잠금 안내만 보인다.
- 내부결재 작성: 급여 내역은 읽기 전용이다. 결재선, 참조자, 근거 문서, 첨부를 정한다.
- 내부결재 상세·인쇄: 급여 내역과 과목별 예산 현황. 이사장이 아니면 인원과 합계만.
- 지출완료 확인: 급여 전용 창(지급일, 이체 확인). 금액 입력과 통장 연결이 없다.
